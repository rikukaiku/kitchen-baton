# キッチンバトン 開発状況まとめ

## プロジェクト概要

子ども食堂を始めたい人と、場所・設備を提供したい人をマッチングするアプリ「キッチンバトン」。
現在は東京都・埼玉県の子ども食堂と公共施設のデータを地図上に可視化するところまで完成しています。

データはすべて **CC BY 4.0**（クリエイティブ・コモンズ 表示）ライセンスのオープンデータを使用し、出典は `data/SOURCES.md` に一覧化しています。個人の電話番号・メールアドレスなどの連絡先情報は、公開する地図データからは除外しています。

## 実装済みの機能

**地図・検索**
- 都道府県・市区町村での絞り込み検索（五十音順に整理済み）
- 「場所の種類」を複数選択可能（子ども食堂と公民館を同時に表示、等）
- ピンが密集して見づらい問題を解消（件数表示→ズームで個別ピンに分解。ガッコムの子ども食堂マップを参考に導入）
- 検索結果カードをクリックすると地図が移動し、該当ピンの吹き出しも自動表示
- 「↺ リセット」ボタンで表示位置・検索条件を初期状態に戻せる
- 初期表示は東京都庁付近（23区のほぼ中心）

**分析**
- 区市町村ごとの0〜14歳人口と食堂数を掛け合わせた空白地域（ギャップ）分析。食堂ゼロの区市町村が25件判明（新宿区・墨田区など人口の多い区も含む）

## 技術構成

- フロントエンド：React + TypeScript + Vite、地図はLeaflet（react-leaflet）
- ホスティング：Vercel（`main`ブランチに自動連動）
- データ収集：Pythonスクリプト（`data/raw/`）で東京都オープンデータカタログのAPIから収集→ジオコーディング→重複除去→地図用GeoJSONと出典一覧を生成
- 収集の手順は再利用できるようClaude Codeの「スキル」として `.claude/skills/tokyo-opendata-collector/` に整備済み

**このスキルの使い方**：スキルはこのリポジトリ内（`.claude/skills/`）に置いてあるので、このリポジトリをClaude Codeで開いている人なら誰でも使えます。特別な操作は不要で、例えば

> 「空き家データを地図に追加して」
> 「飲食店（間借りできそうなところ）のオープンデータを探して」

のように、次に追加したいデータの種類を伝えるだけで、Claude Codeが自動的にこのスキルを参照します。中身は、子ども食堂・公民館データを集めたときに実際にうまくいった手順（東京都オープンデータカタログのAPIで類義語を複数試しながら候補データセットを探す→自治体ごとにバラバラなCSVの形式を判定する→目的の施設だけに絞り込む→住所から緯度経度を補う→重複を除く→連絡先情報を除いて仕上げる、という一連の流れ）と、そこで実際に踏んだバグ（住所が不完全で位置がずれる、カテゴリ名がキーワードに誤って一致してしまう等）の対処法です。エンジニアが毎回ゼロから収集方法を考え直さなくても、同じ品質で次のデータを追加できるようにするためのものです。

## 見えてきた課題

1. **民間サイトの情報は自動で取り込めない**：例えば新宿区社会福祉協議会のサイトには子ども食堂の掲載があるが、オープンデータカタログには載っていない。著作権・利用規約の関係で無断スクレイピングはできず、人による許諾確認が必要（データ・パートナーシップ担当の出番になりそう）
2. **施設の設備情報（炊事場・冷蔵庫の有無等）はオープンデータに無い**：施設提供者自身に登録してもらうフォームが必要（今の「＋場所を登録」ボタンは見た目だけで未実装）
3. **バックエンド・DBが無い**：現状は静的ファイル配信のみで、ユーザー登録・施設登録は動いていない
